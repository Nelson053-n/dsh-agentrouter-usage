# AgentRouter usage for DeepSeek Harness

Панель «Использование» с подключением кабинета AgentRouter, его балансом и отдельным учётом токенов, ответов и сессий DSH.

> Репозиторий содержит только исходники, тесты и ресурсы плагинов. Каждый пользователь вводит **свои** ключи у себя в Harness. Не передавайте коллегам профиль, токены, cookies или историю сессий.

## Что входит

| Компонент | Назначение |
| --- | --- |
| `packages/usage-ledger` — `@local/usage-ledger` | Host: учёт токенов, API балансов, проверка и сохранение подключения кабинета |
| `packages/token-usage` — `@local/token-usage` | Web UI: страница «Использование», стоимость сессии и форма AgentRouter |
| `dsh-llm-agentrouter@2.6.1` | Внешний плагин подключения моделей AgentRouter; устанавливается отдельно из npm |

Корень репозитория — проект разработки, **не Harness bundle**. Устанавливать нужно оба подкаталога `packages/*`.

## Возможности

- Фактический баланс кабинета AgentRouter; накопленный расход и число запросов, если они возвращаются API.
- Подключение по **Access token кабинета** и числовому **User ID / New-Api-User**.
- Проверка токена и соответствия ID **до** сохранения; отключение кабинета без изменения API-ключа моделей.
- Отдельные токены, ответы и сессии AgentRouter по `message.source.provider`, без угадывания провайдера по модели.
- Квота ключа отдельно от баланса аккаунта — только если сервер поддерживает соответствующий API.
- Время обновления, явные ошибки и пометка устаревших данных вместо ложного нулевого баланса.
- Стандартная панель общего расхода DSH, оценка стоимости по моделям, дням и проектам.
- Интерфейс на русском, английском и китайском.

## Требования

- DeepSeek Harness с Web/Desktop-профилем. Проверенный контракт: **0.2.2-rc.1**. Совместимость с другими версиями нужно проверять отдельно.
- Установленный внешний bundle **`dsh-llm-agentrouter@2.6.1`** для моделей и обнаружения текущего endpoint.
- Для тестов: Node.js **22+**, рекомендуется Node.js 24.
- Для исходников панельных плагинов не нужны сборка, дополнительные npm-зависимости или копия React: они используют клиентскую среду Harness.

## Установка для коллег

### 1. Получите исходники

```sh
git clone https://github.com/Nelson053-n/dsh-agentrouter-usage.git
```

Можно также скачать **Code → Download ZIP**, распаковать в постоянную папку и открыть её в Harness. Не удаляйте/не перемещайте папку после установки: менеджер может связать локальные bundles с ней.

### 2. Установите три компонента через Harness

Откройте сессию Harness в папке клонированного проекта и попросите агента:

```text
Установи в текущий профиль:
1. bundle dsh-llm-agentrouter@2.6.1 из npm;
2. локальный bundle packages/usage-ledger;
3. локальный bundle packages/token-usage.
Используй менеджер плагинов Harness, не редактируй профиль вручную.
```

Агент должен передать абсолютные пути к локальным пакетам в `plugin_manager` с `action: install_bundle`. Подтвердите необходимые запросы менеджера. Изменения профиля распространяются на все его сессии.

Если bundle с таким именем уже установлен, сначала проверьте его источник/версию и следуйте `nextStep` менеджера. Не выключайте чужие провайдеры и не заменяйте профиль целиком.

После установки следуйте полю `application`/`nextStep`; если требуется перезапуск, полностью перезапустите Harness. Обновите существующую Web-страницу.

### 3. Подключите модели AgentRouter

В настройках моделей Harness укажите **API-ключ моделей** для `AGENTROUTER_API_KEY`. Это ключ из раздела управления API-ключами AgentRouter, обычно начинающийся с `sk-`.

Выбор CN/Intl endpoint настраивается в карточке внешнего плагина AgentRouter. Подробности и поддерживаемые модели описаны в [его документации](https://github.com/aqiu817/dsh-llm-agentrouter).

### 4. Подключите баланс кабинета

В Harness откройте:

**Использование → AgentRouter → Подключить кабинет**

1. Введите **Access token кабинета**, а не ключ моделей `sk-…`.
2. Введите числовой **User ID / New-Api-User**.
3. Проверьте показанный HTTPS адрес назначения.
4. Подтвердите согласие на чтение баланса и локальное хранение токена.
5. Нажмите **Проверить и сохранить**.

После успешной проверки токен хранится только штатным credential service на Host и не возвращается через API. При отмене/отключении API-ключ моделей не меняется. Сохранённый токен привязан к одобренному origin: переключение маршрута моделей не отправляет его новому серверу автоматически.

## Где взять токен и ID

Откройте [личную страницу AgentRouter](https://agentrouter.org/console/personal) и войдите в свой аккаунт.

- **Токен:** Personal Settings → Security Settings → System Access Token. На китайском: 个人设置 → 安全设置 → 系统访问令牌. В обновлённом интерфейсе раздел может называться Access Tokens. Создайте и скопируйте токен. **Regenerate в старом интерфейсе заменяет предыдущий токен** и может нарушить другие подключения.
- **ID:** числовой User ID / 用户 ID в профиле. Если его не видно, откройте F12 → Network, обновите страницу, найдите `/api/user/self` и скопируйте только `data.id` из ответа.

[Описание пути к System Access Token для AgentRouter](https://github.com/cheaper-inference/OmniRoute/issues/6850).

Не публикуйте полный ответ профиля, токен или заголовок Authorization в issue, скриншоте или чате.

## Безопасность и ограничения

- Токен кабинета может иметь права управления аккаунтом. Плагин использует его только для `GET /api/user/self`; `/api/status` запрашивается без токена. Автоматический вход, сбор cookies, создание токенов и изменение внешнего аккаунта не выполняются.
- Локальное хранилище Harness — **не обещание шифрования или изоляции от программ, работающих под тем же OS-пользователем**. Секрет не входит в этот репозиторий и не пишется плагином в историю чата/хранилище браузера.
- Все HTTP-сводки публичной сборки требуют авторизации Harness. Подключение/отключение кабинета разрешено только browser Peer, не общему API Peer и не агентскому инструменту.
- Обновление баланса кэшируется на 60 секунд; последний успешный ответ при временной ошибке помечается устаревшим и используется не дольше 15 минут.
- Квота ключа, баланс аккаунта и токены DSH — разные показатели. Наличие баланса не гарантирует доступность общих пулов моделей.
- Тарифы в панели — оценка, не счёт AgentRouter. Если валюта/коэффициент квоты не подтверждены status API, показываются единицы квоты.
- Дубли импортированных сессий могут завысить локальный расход. День определяется локальной зоной Host.
- Дополнительные источники панели при наличии их локальных учётных данных: DeepSeek, OpenRouter, Anthropic и Codex CLI. Codex-источник может читать собственные локальные журналы и OAuth auth-файл CLI; он не входит в баланс AgentRouter.
- Тесты подтверждают контракт и ограничения доступа на искусственных данных. Реальную работу кабинета и отрисовку нужно проверить в собственной установке Harness.

Подробнее: [политика безопасности](SECURITY.md).

## Проверка разработки

```sh
node scripts/verify.mjs
```

Или `npm test`. Установка зависимостей для этих тестов не нужна. Проверки выполняются без реальных токенов, не обращаются к LLM и не расходуют квоту моделей:

- синтаксис и состав пакетов;
- метаданные, exports и ресурсы;
- проверка исходников на секреты/личные пути;
- серверные тесты квоты и подключения кабинета;
- клиентский контракт, локализация и арифметика стоимости.

## Обновление

Сначала получите изменения репозитория (`git pull --ff-only`), затем обновите оба локальных bundles через менеджер плагинов. После обновления следуйте `nextStep` и обновите страницу. Не копируйте credential store или пользовательский профиль между компьютерами.

## English summary

This repository distributes two linked DeepSeek Harness bundles: a Host usage ledger and a Web usage panel. Install the separately maintained `dsh-llm-agentrouter@2.6.1`, then install both package directories using the Harness Plugin Manager. Each colleague supplies their own model API key and, separately, their AgentRouter dashboard access token plus numeric user ID.

The dashboard token is verified before saving, stays in the Host credential service, is pinned to an approved HTTPS origin, and can be disconnected without altering the model key. The repository contains no account/profile data. Run `node scripts/verify.mjs` for dependency-free, offline tests.
